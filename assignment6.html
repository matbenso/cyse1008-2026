5) Set up Stripe webhooks with the VS Code extension

A webhook is how Stripe notifies your app that a payment completed. When running locally, Stripe cannot reach your machine directly — the Stripe VS Code extension solves this by forwarding webhook events from Stripe's servers to your local dev server in real time.

You will end up with two Stripe keys in your .env.development:

  • STRIPE_SECRET_KEY — copied from the Stripe dashboard (step 4 above). This authenticates your app with Stripe's API.
  • STRIPE_WEBHOOK_SECRET — generated locally when you start the webhook forwarder (this step). This lets your app verify that incoming webhook events really came from Stripe and not from someone else.

There are two ways to start the forwarder — Option A uses the VS Code extension (recommended), Option B uses the terminal directly (simpler if the extension gives you trouble). Both produce the same webhook secret. Pick one.

Option A — VS Code Stripe extension

Step A1: Install the extension

  1. Open VS Code. Press Ctrl+Shift+X (Windows/Linux) or Cmd+Shift+X (Mac) to open the Extensions panel.
  2. Search for Stripe and install the extension published by Stripe (the one with the S logo).
  3. After it installs, a new Stripe S icon appears in the left sidebar. Click it to open the Stripe panel.
  4. Click Sign in and choose GitHub or email. Your browser will open — follow the prompts and return to VS Code once authorised.

Step A2: Check (or create) the launch configuration file

The project includes a .vscode/launch.json file that tells the extension which URL to forward webhooks to. After fetching the latest code from upstream it should already be there. To confirm: look in the project root for a folder named .vscode containing a file named launch.json.

If the file is missing, create it now:

  1. In the project root, create a folder named .vscode (if it does not exist).
  2. Inside it, create launch.json with exactly this content — the forwardTo URL must match the port your dev server runs on (3032): 
    {
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Stripe: Forward webhooks",
      "type": "stripe",
      "request": "launch",
      "command": "listen",
      "forwardTo": "http://localhost:3032/api/stripe/webhook"
    }
  ]
}
  3. Save the file.

Step A3: Start the forwarder

  1. Open the Run and Debug panel:
    • Windows/Linux: press Ctrl+Shift+D
    • Mac: press Cmd+Shift+D
    • Or click the play icon with a small bug in the left sidebar (it looks like ▷ with a beetle).
  2. At the very top of the Run and Debug panel there is a dropdown (it may say "No Configurations" or the name of a previous config). Click that dropdown and choose "Stripe: Forward webhooks".
  3. Click the green play ▶ button to the left of the dropdown.
  4. A DEBUG CONSOLE or terminal tab opens at the bottom of VS Code. After a few seconds you will see a line like: 
    > Ready! Your webhook signing secret is whsec_abc123...
    Scroll up if you do not see it immediately — it prints near the top when the forwarder starts.
  5. Copy the full whsec_... value and continue to Step C below.

Option B — Terminal (no extension needed)

  1. Open a new terminal in VS Code (Ctrl+` or Cmd+` on Mac, or Terminal → New Terminal from the menu).
  2. Log in to Stripe CLI (only needed the first time): 
    stripe login
    A browser window will open — authorise it and return to the terminal.
  3. Start the forwarder. Make sure the port matches your dev server (3032): 
    stripe listen --forward-to http://localhost:3032/api/stripe/webhook
  4. After a few seconds you will see: 
    > Ready! Your webhook signing secret is whsec_abc123...
    Copy the full whsec_... value.
  5. Leave this terminal running — closing it stops the forwarder.

Step C — Add the webhook secret to your environment

  1. Open .env.development in the project root.
  2. Add this line (paste your own whsec_... value): 
    STRIPE_WEBHOOK_SECRET=whsec_paste_your_secret_here
  3. Save the file. It should now contain both keys: 
    STRIPE_SECRET_KEY=sk_test_...
STRIPE_WEBHOOK_SECRET=whsec_...
  4. Restart the dev server (npm run dev) so it picks up the new value.

Important: The whsec_... secret is tied to the current forwarder session — it changes every time you restart it. If you stop and restart the forwarder, copy the new secret into .env.development and restart the dev server.

Troubleshooting:

  • "Stripe CLI not found" — the Stripe CLI is not installed. On Linux/WSL run: 
    curl -s https://packages.stripe.dev/api/security/keypair/stripe-cli-gpg/public | gpg --dearmor | sudo tee /usr/share/keyrings/stripe.gpg > /dev/null
echo "deb [signed-by=/usr/share/keyrings/stripe.gpg] https://packages.stripe.dev/stripe-cli-debian-local stable main" | sudo tee /etc/apt/sources.list.d/stripe.list
sudo apt update && sudo apt install stripe
    On Mac with Homebrew: brew install stripe/stripe-cli/stripe
    Then restart VS Code and try again.
  • Run and Debug dropdown is empty / "No Configurations" — the .vscode/launch.json file is missing. Follow Step A2 above to create it, or use Option B (terminal) instead.
  • "Webhook signature verification failed" — the STRIPE_WEBHOOK_SECRET in .env.development does not match what the forwarder printed. Copy it again carefully and restart the dev server.
  • Order stays Pending after payment — the webhook did not reach your app. Check that the forwarder is still running (terminal or Run and Debug panel), and that you restarted the dev server after saving .env.development.

Change 1 - Backend: add customer_email to the API response

Open src/app/api/stripe/confirm-session/route.js.

This route has two separate return NextResponse.json({...}) calls — one for when Stripe has not yet confirmed payment (paid: false, around line 32) and one for when payment is confirmed (paid: true, around line 62). You need to add customer_email to both.

First return (around line 32 — payment not yet confirmed):

// Before
return NextResponse.json({
  ok: true,
  paid: false,
  status: session.status,
  payment_status: session.payment_status,
  amount_total: session.amount_total,
  currency: session.currency,
  orderId: session.metadata?.orderId ?? null,
});

// After
return NextResponse.json({
  ok: true,
  paid: false,
  status: session.status,
  payment_status: session.payment_status,
  amount_total: session.amount_total,
  currency: session.currency,
  orderId: session.metadata?.orderId ?? null,
  customer_email: session.customer_email ?? null,
});

Second return (around line 62 — payment confirmed):

// Before
return NextResponse.json({
  ok: true,
  paid: true,
  status: session.status,
  payment_status: session.payment_status,
  amount_total: session.amount_total,
  currency: session.currency,
  orderId,
});

// After
return NextResponse.json({
  ok: true,
  paid: true,
  status: session.status,
  payment_status: session.payment_status,
  amount_total: session.amount_total,
  currency: session.currency,
  customer_email: session.customer_email ?? session.customer_details?.email ?? null,
  orderId,
});

The second return uses session.customer_details?.email as a fallback because Stripe populates customer_email only when an email was passed when creating the session; customer_details.email is always filled in once the customer completes the Stripe checkout form.

Troubleshooting Documentation

If something does not work as expected, include a short note describing what problem you encountered, what you tried, and what happened. A screenshot of an error message counts as troubleshooting evidence. Work through the sections below in order — most issues have a clear cause and a one-line fix.

Checkout does not complete or order stays "pending"

  • Dev server not restarted after editing .env.development
    Next.js only reads environment variables at startup. Any time you add or change STRIPE_SECRET_KEY or STRIPE_WEBHOOK_SECRET, stop the server (Ctrl+C) and run npm run dev again.
  • Wrong Stripe key (live key instead of test key)
    Your STRIPE_SECRET_KEY must start with sk_test_. If it starts with sk_live_ you are using your production key — remove it and paste the correct test key from the Stripe dashboard (Developers → API keys → Secret key → Reveal test key).
  • Webhook forwarder is not running
    Open the Run and Debug panel (Ctrl+Shift+D / Cmd+Shift+D), choose "Stripe: Forward webhooks" from the dropdown, and click the green ▶ button. Or run this in a terminal: 
    stripe listen --forward-to http://localhost:3032/api/stripe/webhook
    You must see the line Ready! Your webhook signing secret is whsec_... before you test a checkout.
  • STRIPE_WEBHOOK_SECRET is missing or stale
    The whsec_... secret changes every time you restart the forwarder. Copy the new value from the terminal, paste it into .env.development, and restart the dev server. To confirm the right secret is loaded, check the terminal — the webhook route logs the first 8 characters of the secret on every incoming event (stripeWebhook secret: whsec_ab). Compare that to what the forwarder printed.
  • Secret still seems wrong even after updating .env.development and restarting
    Next.js caches compiled code and environment values in the .next folder. Occasionally a stale cached value survives a normal restart, so the old secret keeps being used even though .env.development has the new one. The fix is to delete the cache and do a clean restart: 
    # Stop the dev server first (Ctrl+C), then:
rm -rf .next

# Windows (PowerShell):
Remove-Item -Recurse -Force .next
    Then run npm run dev again. Next.js will rebuild from scratch and read the current value from .env.development. After it starts, check the terminal for stripeWebhook secret: whsec_ab on the next webhook event and confirm it matches the forwarder output.
  • Stripe event is arriving but order still shows "pending" in Firestore
    This means the webhook handler ran but the Firestore update was skipped or failed. Check the Next.js terminal for a line starting with Webhook handler error. The most common cause is that the orderId was not saved in the Stripe session metadata — this happens if checkout was started before the latest code was pulled. Pull the latest upstream code, restart, and try a fresh checkout.

    To replay the last event without going through checkout again, find the event ID in the Stripe CLI output (it looks like evt_1ABC...) and run: 
    stripe events resend evt_1ABC...
    Then watch the Next.js terminal for the result.
  • Success page stays on the loading spinner
    The page polls /api/stripe/confirm-session until Stripe confirms payment. If it never resolves, open DevTools (F12 → Network), find the confirm-session requests, and check the response. A 400 or 500 response means the API route is erroring — look at the Next.js terminal for the error message. A common cause is a missing or wrong STRIPE_SECRET_KEY.

Firebase emulators not running or Firestore data missing

  • firebase.json is missing
    The Firebase CLI needs firebase.json in the project root to know which emulators to start and on which ports. This file is intentionally excluded from Git (it is in .gitignore) so that each student can have their own local copy. If the file does not exist, the emulator will not start and you will see an error like "Cannot find firebase.json" or "Not in a Firebase app directory".

    To check: look in the project root for a file named firebase.json. If it is missing, create it now with exactly this content: 
    {
  "functions": { "source": "functions", "runtime": "nodejs20" },
  "firestore": {
    "database": "(default)",
    "rules": "firestore.rules",
    "indexes": "firestore.indexes.json"
  },
  "storage": { "rules": "storage.rules" },
  "emulators": {
    "functions": { "port": 5001 },
    "firestore":  { "port": 8080 },
    "auth":       { "port": 9099 },
    "storage":    { "port": 9199 },
    "ui":         { "enabled": true, "port": 4000 },
    "hosting":    { "port": 5000 },
    "singleProjectMode": true
  },
  "hosting": { "source": ".", "frameworksBackend": {} }
}
    Save the file, then run npm run dev again.
  • Emulators not started
    The npm run dev command starts both the Next.js server and the emulators together. If you ran npm run dev:web instead, the emulators are not running. Stop everything and use npm run dev. Confirm the emulators are up by visiting http://localhost:4000 — you should see the Firebase Emulator UI.
  • Firestore shows no data / orders collection is empty
    The emulator starts with an empty database unless there is existing data in the .firebase-data folder. This is expected on a fresh clone. Complete a checkout — a new order document will appear in the orders collection immediately. If you complete a checkout and still see nothing, check that the emulator UI at http://localhost:4000/firestore is connected (not showing a connection error) and that the webhook fired successfully (see above).
  • Port already in use (EADDRINUSE)
    If another process is using port 8080, 9099, or 4000, the emulator will fail to start. Find and stop the conflicting process: 
    # Linux / Mac
lsof -i :8080
kill -9 <PID>

# Windows (PowerShell)
netstat -ano | findstr :8080
taskkill /PID <PID> /F
    Then run npm run dev again.
  • Emulator crashes immediately with a Node version error
    The project's firebase.json sets "runtime": "nodejs20" for Cloud Functions. If your local Node version is older than 20, the Firebase Functions emulator will refuse to start and take the entire dev server down with it (because both run together via npm run dev). See the Node version section below.

Appendix — Installing nvm (Node Version Manager)

nvm lets you install and switch between multiple Node versions on the same machine. It is the easiest way to ensure you are running the right version for a given project. This assignment requires Node 20.

Mac and Linux (including WSL on Windows)

Run this single command in your terminal — it downloads and runs the nvm install script:

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash

After it finishes, close and reopen your terminal (or run source ~/.bashrc / source ~/.zshrc to reload your shell config). Then confirm nvm is available:

nvm --version

Now install and activate Node 20:

nvm install 20
nvm use 20
nvm alias default 20

The last command makes Node 20 the default for all future terminal sessions. Confirm with:

node -v   # should print v20.x.x

Windows (without WSL)

The standard nvm script does not run natively on Windows. Use nvm-windows instead:

  1. Go to the nvm-windows releases page and download nvm-setup.exe from the latest release.
  2. Run the installer and follow the prompts. Accept the default install paths.
  3. Open a new PowerShell or Command Prompt window (not the one you had open before — nvm-windows needs a fresh session).
  4. Install and activate Node 20: 
    nvm install 20
nvm use 20
  5. Confirm: 
    node -v   # should print v20.x.x

Note: on Windows you may need to run PowerShell as Administrator for the nvm use command to work.

Useful nvm commands

Command What it does
nvm install 20 Download and install the latest Node 20 release
nvm use 20 Switch the current terminal session to Node 20
nvm alias default 20 Make Node 20 the default for all new terminals (Mac/Linux only)
nvm ls List all Node versions you have installed
node -v Show the currently active Node version
